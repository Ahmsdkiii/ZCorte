### H.1 Customer

#### FR-001 — Homepage `[P+]` · Must

| Field            | Isi                                                                                                                                                                        |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description      | Halaman utama dengan hero, premise, pinned story, kartu koleksi, katalog featured, closing — sesuai 6 section prototype                                                    |
| Objective        | Memperkenalkan brand & mengarahkan ke koleksi/katalog                                                                                                                      |
| User role        | Visitor, Customer, Owner                                                                                                                                                   |

| Alternative flow | A1: data story kosong → section pinned story disembunyikan. A2: gambar gagal dimuat → placeholder `surface-raised`                                                         |
| Validation       | Hanya produk `ACTIVE` ditampilkan; jumlah featured maks 6                                                                                                                  |
| Expected result  | Halaman render tanpa layout shift; tautan valid                                                                                                                            |
| AC               | (a) Semua section prototype hadir; (b) LCP gambar hero ≤ 2,5 dtk pada profil Lighthouse Mobile; (c) hanya ada satu `<h1>`; (d) JSON-LD Organization & WebSite valid        |

#### FR-007 — Checkout `[P+]` · Must

| Field            | Isi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description      | Form kontak, alamat, metode pengiriman (`standard` gratis / `express` Rp45.000 — nilai prototype, tarif tetap dikonfigurasi Owner lewat `ShippingProvider`; pengiriman fisik dilakukan toko), metode pembayaran, langkah **"Periksa alamat"**, ringkasan                                                                                                                                                                                                                                                                                                                                                               |
| Objective        | Mengubah bag menjadi pesanan yang valid & terbayar, dengan identitas pembeli jelas (mengurangi spam dan salah alamat)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| User role        | **Customer** (login wajib)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Preconditions    | Pengguna login; bag tidak kosong; semua item tersedia                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Main flow        | 1) Visitor menekan Checkout → diarahkan ke login/daftar, lalu kembali ke checkout dengan bag terbawa (`mergeGuestCart`). 2) `OrderService.expireDueOrders()` mengevaluasi pesanan kedaluwarsa secara lazy untuk melepas stok jatuh tempo. 3) Pilih alamat tersimpan atau isi baru. 4) Pilih pengiriman & pembayaran. 5) Layar **Periksa alamat**: ringkasan penerima, alamat, telepon; pelanggan mengonfirmasi. 6) Submit → Server Action `placeOrder`: validasi Zod → transaksi DB (cek & kurangi stok, buat Order+OrderItem snapshot, Payment `PENDING`) → inisiasi pembayaran. 7) Redirect ke pembayaran/konfirmasi |
| Alternative flow | A1: stok kurang saat submit → rollback, pesan per item, bag diperbarui. A2: kode promo tidak valid → galat di kolom promo. A3: gateway gagal → pesanan `PENDING_PAYMENT` tetap ada, tombol "Bayar ulang" (`retryPayment`, FR-008). A4: sudah ada 3 pesanan `PENDING_PAYMENT` → ditolak dengan pesan "selesaikan atau batalkan pesanan sebelumnya" (`cancelMyOrder`, FR-009). A5: sesi habis saat submit → login ulang, form dipertahankan                                                                                                                                                                              |
| Validation       | email RFC-valid; telepon `^(\+62\|62\|0)8[0-9]{8,12}$`; nama 1–60; alamat 5–200; kota & provinsi wajib; kode pos `^\d{5}$`; catatan ≤ 250. **Server menghitung ulang total; nilai dari client diabaikan**                                                                                                                                                                                                                                                                                                                                                                                                              |
| Expected result  | Order dengan nomor unik server-side (`{PREFIX}-YYMM-NNNN`), stok dicadangkan melalui `InventoryMovement(RESERVE)`, lalu dilepas saat pesanan dibatalkan/kedaluwarsa                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| AC               | (a) `idempotencyKey` sama untuk user yang sama tidak membuat dua pesanan; (b) dua pembeli berebut stok terakhir → tepat satu berhasil; (c) pengguna tanpa login tidak dapat memanggil `placeOrder` (401); (d) maksimum 3 pesanan `PENDING_PAYMENT` per akun; (e) setiap reserve/release tercatat; (f) tanpa opsi COD                                                                                                                                                                                                                                                                                                   |

#### FR-008 — Pembayaran `[P+]` · Must

| Field            | Isi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description      | Pilihan Virtual Account, QRIS, dan Kartu dari UI prototype melalui antarmuka `PaymentGateway`. **R0:** adapter simulasi (Bayar/Gagal). **R1:** adapter sandbox dipilih setelah verifikasi dokumentasi provider terbaru                                                                                                                                                                                                                                                                                                                                                                       |
| Objective        | Pembayaran dengan verifikasi aman; status pembayaran konsisten di seluruh sistem                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| User role        | Customer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Preconditions    | Order `PENDING_PAYMENT`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Main flow        | 1) `PaymentService` memilih adapter berdasarkan env. 2) R0 membuka halaman simulasi; R1 membuat charge sandbox. 3) Adapter simulasi (`simulatePayment`) atau webhook terverifikasi memanggil `PaymentService.markPaid`. 4) Payment dan Order menjadi `PAID`, lalu event `ORDER_PAID` dicatat. 5) Jika gagal/ingin ganti metode selama masih `PENDING_PAYMENT` dan belum lewat `expiresAt`, Customer memanggil `retryPayment` yang menandai `Payment(PENDING)` sebelumnya menjadi `EXPIRED`/`FAILED` dan membuat baris `Payment(PENDING)` baru (maksimal 1 Payment `PENDING` aktif per order) |
| Alternative flow | A1: kedaluwarsa (24 jam; di R0 dievaluasi lazy oleh `expireDueOrders()` + tombol Owner + cron) → Payment/Order `EXPIRED`, stok dilepas. A2: callback ganda → idempoten. A3: pembayaran gagal → pesanan tetap `PENDING_PAYMENT`, tombol "Bayar ulang" (`retryPayment`). A4: jumlah tidak cocok → Payment `NEEDS_ATTENTION`; order tidak menjadi `PAID`                                                                                                                                                                                                                                        |
| Validation       | R1 mengikuti skema signature resmi provider yang dipilih; jumlah dibayar harus sama dengan `Order.total`; signature dibandingkan konstan-waktu. Request dengan signature salah ditolak tanpa mengubah data                                                                                                                                                                                                                                                                                                                                                                                   |
| Expected result  | Status pembayaran konsisten antara DB, UI, dan Telegram                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| AC               | (a) Hanya adapter simulasi di environment demo yang boleh menandai pembayaran tanpa webhook; (b) callback salah tidak diproses dan dicatat; (c) jumlah tidak cocok → `NEEDS_ATTENTION`; (d) data kartu tidak menyentuh server aplikasi; (e) total selalu dihitung server                                                                                                                                                                                                                                                                                                                     |
| Catatan          | Pemilihan vendor sandbox/produksi bukan bagian R0 dan harus diverifikasi terhadap dokumentasi, biaya, serta persyaratan akun terbaru                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

#### FR-009 — Konfirmasi, Pelacakan, Perubahan Alamat & Pembatalan Pesanan `[R]` · Must

| Field            | Isi                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description      | Layar konfirmasi (dari prototype) + `/account/orders` (daftar) dan `/account/orders/[orderNumber]` (detail), termasuk ubah alamat dan pembatalan sebelum bayar                                                                                                                                                                                                                                                                                                                                                                                                        |
| Objective        | Transparansi status pesanan, kesempatan memperbaiki alamat yang salah, dan pembatalan mandiri sebelum bayar                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| User role        | Customer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Preconditions    | Pesanan milik pengguna login (daftar pesanan mengevaluasi `expireDueOrders()` secara lazy)                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Main flow        | Tampilkan nomor, item, total, pengiriman, timeline (`PENDING_PAYMENT → PAID → PROCESSING → SHIPPED → COMPLETED`), nama kurir + nomor resi bila ada (tombol "Lacak di situs kurir" berupa tautan ke situs resmi kurir, tanpa API). Selama status `PENDING_PAYMENT`, tersedia tombol **"Bayar ulang"** (`retryPayment`) dan **"Batalkan pesanan"** (`cancelMyOrder`, melepas stok via `InventoryMovement(RELEASE)` secara atomik dan menandai Payment `PENDING` sebagai `EXPIRED`/`FAILED`). Selama status `PENDING_PAYMENT` atau `PAID`, tombol "Ubah alamat" tersedia |
| Alternative flow | A1: pesanan milik user lain → 404 (tidak membocorkan keberadaan). A2: status sudah `PROCESSING`+ → perubahan alamat hanya lewat Owner (kontak pelanggan terlihat di dashboard Owner). A3: Customer mencoba membatalkan order berstatus `PAID`+ → ditolak `409 INVALID_STATE_TRANSITION`                                                                                                                                                                                                                                                                               |
| Validation       | Alamat baru memakai skema Zod yang sama dengan checkout; perubahan alamat & pembatalan dicatat di `OrderStatusHistory`/audit                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Expected result  | Hanya pemilik pesanan yang dapat melihat, membatalkan sebelum bayar, dan mengubah alamat                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| AC               | (a) Customer A tidak dapat membuka/membatalkan/mengubah pesanan Customer B (uji otorisasi IDOR); (b) timeline sesuai riwayat; (c) ubah alamat ditolak setelah `PROCESSING`; (d) `cancelMyOrder` hanya sukses saat `PENDING_PAYMENT` dan mengembalikan stok tepat satu kali                                                                                                                                                                                                                                                                                            |
